## kvq: int8 KV cache

- Check: no endpoint shows the KV type (README.md:315 says /props does; serve/src/main.rs:506-519 returns only n_ctx and model): compare `pack-fit PACK --tmax N` and the memory used

## tmax: Context window

- Enable: BARO_TMAX (engine restart). Dense models (llama, qwen2, granite): tools/baro serve rebuilds the engine once per value (about 35 s, own cache slot); the bare dense engine ignores it. Check /health limits.tmax
- Default: 16384 in the face and tools/baro; baro-serve 32768; the bare engine 1088
- Best standard: Never below 16384. Prefill is quadratic in the prompt (Qwen2.5-7B q4_K_M: 14.8k tokens 39 s, 61k tokens 617 s), so a 98304 window is cheap to hold (19.9 GB VRAM) and expensive to fill. Size it against FREE VRAM, measured (`rocm-smi --showmeminfo vram`, then `pack-fit PACK --tmax N --used-gb X`); the desktop and other GPU programs count.
- Status: WORKS
- In the GUI: Engine tab (BARO_TMAX basic); Apply shows the pack-fit verdict and blocks on NO
- Check: GET /health `limits.tmax` (and /props `default_generation_settings.n_ctx`); `pack-fit`
- Source: README.md:405-408; face/apply.mojo; bench/min16k.sh

## parallel: Many sessions on one engine

- Enable: build the engine with -D BARO_SEQ_CAP=N -D BARO_SLOTS=2, then `baro-serve --engine E --pack KQPACK --parallel N --kv-pool P [--max-inflight Q]` (flags, not env; tools/baro serve does not pass them)

- Status: WORKS
