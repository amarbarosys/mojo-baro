One window: chat on the left, the live engine panel on the right, opened by `tools/baro gui`. Built on mojo-imkit
v0.9.0, vendored. Source of the round: `docs/lanes/2026-11-10-next-steps.md` section A. Owner decisions 2026-11-12:
Round A scope only (no README restyle), herdr lanes. Prerequisites met: cpu-tier merged (017ad93), front real-engine
check (ee69934).

## Standing rules for every lane
- Load skills first: `.claude/skills/mojo-baro`, `mojo-dev`, `lanes`; list them in the report.
- imkit is owned by another pane. This repo never edits imkit. A gap goes into the report as a QUESTION.
- Mojo only (`mojo_language_gate`); Python only as an oracle under `tools/`.
- Display isolation (lanes rule 26): no window on the desktop during gates. Render headless or offscreen to PNG files;
  if imkit cannot render offscreen, say so in the report and stop that step. Every gate runs under
  `systemd-run --user --scope -p MemoryMax=8G`.
- GPU: `gpu-wait run --timeout S` with knobs as `env K=V` inside the queued command; parity and render checks
  `--shared --vram 1`. Read the whiteboard GPU holds first. No run under 16K (`BARO_TMAX>=16384`, max_tokens>=16000).
- Commit each sub-step with a pathspec; no co-author tag; no em dashes. Three failed repairs: write
  `.work/<item>-failure.md`, report, stop.
- Report `docs/lanes/2026-11-12-face-<item>-report.md`: skills loaded, commits, numbers with receipt paths,
  QUESTIONs for imkit, what is UNVERIFIED.

## F0. Shell (one lane, first; F1 and F2 start after it merges)
1. Vendor imkit v0.9.0 as `imkit/` at repo root with the 6-line VENDORED header per file (pattern: `toml/`), and add
   it to the drift loop in `tools/ci-checks.sh` (line ~109). SDL3 and FreeType: checked at start with a named error,
   named in README.
2. Window-cost check (before any widget): resident 9B engine, 20-prompt decode median tok/s, VRAM and `gtt_used`
   with no window, then with an imkit window rendering at 60 fps in the same box. Arms read back from the running
   system (CLAUDE.md P1). If tok/s drops, measure a frame cap (30, 15 fps) and pick by number.
3. Skeleton `face/app.mojo`: window, two panes (left chat, right panel) with placeholder text, talks HTTP to
   `baro-front` (health endpoint only). `tools/baro gui` starts the front if absent and opens the window.
4. Gate: scripted run renders 3 frames to PNG, rapid-ocr reads the placeholder text back, exit non-zero on miss.

## F1. face-chat (lane, after F0)
Message list, input `field`, streaming tokens over SSE from `baro-front`, cancel on close, scroll, copy.
Gate: scripted session sends 2 prompts, renders frames, OCR finds the streamed answer text; cancel test shows the
front saw the disconnect (front log line).

## F2. face-dash (lane, after F0)
Engine state tag, queue depth, tok/s spark line, VRAM bar, active path and fail word from the done line, model card.
Gate: rendered frame OCR reads tok/s and VRAM values that match `rocm-smi`/done-line numbers within 5%.
