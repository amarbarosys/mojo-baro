## Wire seam (frozen; each field has an emitter and a consumer in this round)

Checked before freezing: Rust passes the engine's `finish` through verbatim
(`serve/src/main.rs:788`), and reads done-line fields one by one (`protocol.rs:344-370`), so
added fields break nothing. The engine builds the done line in TWO places
(`engine.mojo:3033` and the pair path near `:1291`): both get every field.

| Field | Line | Emitter (`fix-engine`) | Consumer (`fix-front`) |
|---|---|---|---|
| `"fail":N` | done | B-M1, copy of the mega fail word, 0 on other paths | `DoneStats.fail`; non-zero = `502 engine_invalid_tokens`, SSE error chunk |
| `"finish":"error"` | done | B-M7 (KV exhausted), B-M15 (lens base missing) | passes through as `finish_reason:"error"`; documented |
| `"path":"mega\|mega_win\|spec\|launch\|prefill\|replay\|pair\|seqs"` | done | B-M3 | `timings.path` in the response |
| `"grammar"`, `"gdraws"`, `"gaccepted"`, `"grejected"` | done | B-M6, C6 | `timings`; `grejected > 0` = warning field |
| `"captured":N` | done | B-M13 | `timings` |
| `"load_tier":"hot\|file"` | done | A-M15's real fix | replaces the `load_s < 0.002` guess in `turn.rs` |
| `"tier":"<mode>"`, `"seqs":N` | ready | B-M9, wire gap | `/health`, pool capacity |
| error line for: unknown `latent_id`, prompt past the window after prefix extension, missing lens base | error | B-M5, B-M1, B-M15 | existing error path (400/502) |

A field with no consumer at merge time is a finding, not a done row.

## Method, same for every row (both lanes)

1. **Reproduce first.** Write the test that shows the symptom; it must FAIL on the lane's base
   commit. Keep that failing output as the receipt. A row whose symptom cannot be reproduced is
   reported NOT REPRODUCED with what was tried, and gets no code.
2. Apply the fix named in `docs/state-machines.md` (code 1, 2 or 3). Smallest change; no adjacent refactor.
3. The same test passes. Run the lane's whole test set and compare counts with `.work/fsm-baseline.txt`.
4. One commit per row id, by pathspec: `fix(<area>): <id> <what the user now sees>`, why and numbers in the body.
5. Order by risk: wire words and guards first, tags + transition functions next, startup order and dedupe last.

`fix-front` tests: `cargo test` with a stub engine child (`serve/tests/stub_engine.sh`: ready,
tokens, done, error, dies idle, dies mid-stream, drops done), shell tests for `tools/baro*`
against a fake cache dir, Mojo tests for `latentos/`, `ncm`, `miniagi`.
`fix-engine` tests: pure functions get `serve/test_*.mojo` on CPU (done-line builder, `is_cancel_line`,
`decide_path`, `reset_request_knobs`, `Chain.install/mark_valid`, `PairSeq` transitions);
everything that needs a running engine goes into `bench/fsm-wire-gate.sh` (reuse the shape of
`bench/a3-wire-gate.sh`: preflight check, re-exec under `gpu-wait`, knobs as `env K=V`, stdin fed,
`BARO_TMAX=16384`, fail word read, `EXPLORE=1` until preflight passes). The lane writes the gate
and runs `gate-dryrun` on CPU; the boss runs it on the GPU.
