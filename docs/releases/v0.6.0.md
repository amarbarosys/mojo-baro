# mojo-baro v0.6.0

**Released:** 2026-11-08 · **Commit:** public snapshot `publish-2026-11-08` (one commit on top of `a1c4f4a`) · **Previous:** [v0.5.11](v0.5.11.md)

## What it does

An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

- One engine serves many sessions at once: `baro-serve --parallel N` keeps N requests in flight on a dense K-quant
  pack, shares prompt prefixes read-only, and answers 429 past `--max-inflight` instead of failing mid-decode.
- Q4_K_M files run natively: `engine-pack --kq` keeps the Q4_K / Q6_K rows, decode reads them in the GEMV and the
  megakernel (ids 20/20 against the launch path), and prompt prefill decodes them inside the WMMA GEMM: 1024 tokens in
  0.259 s and 16384 in 4.54 s against llama.cpp's 0.298 and 5.66 s on the same file (Mojo 1.1).
- `/v1/chat/completions` honours OpenAI `tool_choice` (`none`, `required`, a named function; unknown name -> 400).
- Small Llama-family models (spark engine) prefill in batches and decode faster: Llama 3.2 1B prefill of 217 rows
  329 -> 26 ms, split decode attention 2.67x at a 4K context, fused rope 1.028x, all with the same ids.
- The serve layer streams with less memory: streaming detokenizer 10.9 s -> 17 ms and 118 -> 7.4 MB RSS on the lane's test.

## Changes

### Added
- Multi-session decode on dense K-quant packs: `baro-serve --parallel N --max-inflight Q` (sets `BARO_SEQS=N`,
  `BARO_KV_SHARE=1`), engine built with `-D BARO_SEQ_CAP>=N`, `BARO_SEQS_RESERVE`;
  `serve/rows.mojo` step_rows and `amar_gemv_kq_rows` (byte-equal per row to `amar_gemv_kq`, m = 1..8).
- `engine-pack --kq` native K-quant trunks; K-quant row dot in `amar_mega_token`; batched prefill on kq packs and K-quant
  decode in the prefill GEMM's B staging (`BARO_KQ_MMQ`).
- OpenAI `tool_choice` on `/v1/chat/completions`.
- `BARO_NEURONS` (off by default): inject `brain-ask` hits into the last user turn; a `brain_ask` tool loop in `baro serve`.
- Tools: `tools/kernel-facts.sh` (one fact file per kernel in `docs/kernel-facts/`), `bench/ww.sh` wavewait capture
  with goldens in `bench/ww-golden/`.
- `-D BARO_TURBO=1` for the Qwen3.8-27B Turbo bake: spec k=2 61.12 -> 68.72 tok/s same job, ids 19/20.
- `BARO_GTT_REFUSE=1`: the engine warns when GTT grows past a threshold and exits 3 instead of running slow.
- Decode text mode: prompts through the GGUF tokenizer, output printed as text, stops at the GGUF EOS id.
- Q5_0 dequantiser (packs qwen2.5-0.5B Q4_K_M).
- `lab/wavegroup`: the one-model Mojo Llama engine that the spark levers came from, kept as a lever bench.
### Changed
- Toolchain pin Mojo 1.2.0 / MAX 26.7.0 (was 1.1.0). Gated on builds and tests, not on throughput.
- Spark engine: batched prompt prefill (128-row chunks), split decode attention from 128 tokens, fused decode rope,
  split-K QKV GEMV and fused FFN gate+up, all on by default and ids-equal to the old path.
- MoE: hoisted per-block loads in the q6_k grouped down kernel (4.5x on that kernel).
- `engine-pack` quantizes rows on all physical cores (2.8x).
- Bakes hash the tensor bytes and keep the reference outside the file; `baro.mtp` receipt in the self-describing file.
- Repo-wide debloat with byte-identical engines: -1,066 Mojo lines, -315 Python lines, -4,659 shell lines (88 dead
  scripts), C/C++ warnings fixed, the IPC probe hash peak 2.27 GB -> 237 MB.
### Fixed
- Three gates that could not fail (`$(grep)` under `set -e`), and `baro-serve-gate.sh`, `baro-serve-chat-check.sh`,
  `merge-gate.sh` exited 0 on a FAIL verdict.
### Removed
- 22 Python tools and 88 shell scripts with no reference (among them the short-lived `baro-auto`, `baro-sweep`,
  `baro-smoke`).

## Known limits

- On Mojo 1.2 the K-quant megakernel is slower than the launch path: 87.90 vs 98.29 tok/s (88.13 after the delta-phase
  fold), cause open. It is still the default on kq packs; `BARO_MEGA=0` selects the faster launch path.
- The README's llama.cpp ratios were measured on Mojo 1.1.0 or earlier; only the kq megakernel was re-timed on 1.2.
- Multi-session decode is for dense K-quant packs; the MoE pair engine (`BARO_SEQS=2`) is a separate path that
  needs `-D BARO_SEQ_CAP=2`, `BARO_KV_SHARE` and the megakernel.
- `tool_choice: auto` does not constrain tool names: a model can call a tool that is not in the list.
- Many docs cite receipts under `exchange/`, which is local-only and not in this snapshot.

## Upgrade / run

```
uv sync                      # Mojo 1.2.0 / MAX 26.7.0 from PyPI
tools/baro serve MODEL.gguf  # as before
mojo build serve/engine.mojo -I . -I kernels -D BARO_SEQ_CAP=32 -D BARO_SLOTS=2 -o .work/engine-seqs32
BARO_SPEC=0 serve/target/release/baro-serve --engine .work/engine-seqs32 --pack PACK-KQ --parallel 32 --kv-pool 3 ...
# full command: docs/design/multi-session-serve.md
```
