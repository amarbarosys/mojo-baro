## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

- The Qwen3.8-Flash-Next engine (`serve/q4x.mojo`) decodes 6.6% faster: 22.07 -> 20.71 ms/token on the Q2_0 pack,
  same output bit for bit.
- Its batched prefill runs 1.2-1.6x faster at 2048 tokens (5.3-7.5 -> 4.1-5.9 ms/token), byte-identical to decode.
- It can decode speculatively with the model's own MTP head (`Q4X_MTP=mtp.gguf Q4X_SPEC=3`): output identical to plain
  decoding, 2.8 tokens per verify window, but only 1.02x faster today.

## Changes

### Added
- `Q4X_MTP`, `Q4X_SPEC`, `Q4X_SPEC_P`, `Q4X_DRAFT_VOCAB`: MTP speculative decoding for qwen4exp, exact by
  construction (recurrent state ring slots, batched verify) (`b967e03`).
- `Q4X_CPUMISS=N`: compute up to N missed experts per layer on the CPU (AVX-512 VNNI, `serve/q4x_cpu.mojo`); opt-in
  (`bdf2db7`, `b967e03`).
- `bench/q4x-spec.sh`: spec exactness + speed A/B, also a plain A/B against another binary (`b967e03`, `ad3cddd`).
- `ShardIndex.add_file` maps an extra GGUF beside the model (`c3d8c0e`).
- From other lanes in this range: q4x batched prefill `Q4X_PREFILL=1`, byte-exact vs decode (`e4d8799`, `4355056`);
  serve `/v1/ipc/fork`, `/v1/ipc/turn`, sha and stats routes over a T3b HIP IPC checkpoint handoff (`bf2a2df`,
  `e2e40b5`); `icflush` cold-cache ruler and `dsum-diff` (`8cdc3fe`, `e82c539`).
### Fixed
- engine pack: tied embeddings read the output head from `token_embd` (`22d5c2d`).
### Changed
- q4x decode: shared-expert gate fused into the router GEMV, one staging copy per layer, same-type neighbour
  GEMVs run as one launch (bit-exact) (`b967e03`).
- q4x prefill attention: one block per KV head for its 12 query heads past 8 tokens (bit-exact) (`b967e03`).
- A router doorbell that rings late (GPU stall over 5 s) now continues after one synchronize and logs it (`b967e03`).

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- Speculative decoding is 1.02x: the multi-row q4x GEMMs are ALU-bound, so a 3-token verify window costs about as
  much as three steps (`exchange/lane-Q4X-R5-report.md`). Prefill with `Q4X_SPEC` is not supported.
- `Q4X_CPUMISS` measured slower than DMA on a loaded box (18.2 -> 22.8 ms/token at N=2).
- Batched prefill still misses its 2.8 ms/token prereg at T=2048.
