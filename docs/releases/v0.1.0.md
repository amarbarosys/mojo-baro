## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An LLM inference engine for AMD RDNA3 GPUs, with every GPU kernel written in
[Mojo](https://www.modular.com/mojo). It serves chat over an OpenAI-compatible
HTTP API on a single RX 7900 XTX. On matched weights it decodes ahead of
llama.cpp on the dense 9B (Q4_0) and level with it on the 35B MoE; on q8 and
on packs built from Q4_K_M it is still behind.

The point of the project is the kernels. Consumer RDNA3 cards are where most
people actually have 24 GB of VRAM, and they are not what the vendor libraries
are tuned for. This repo measures how much of that gap is real, one
preregistered round at a time.

**Have an AMD GPU that isn't a 7900 XTX?** Your card is the most useful thing
you can contribute. See [docs/amd-family.md](docs/amd-family.md): fifteen
minutes, no model weights needed.

## Highlights

- **Checkpoints you can fork, share and ship.** `POST /v1/checkpoints` saves a prompt's state
  (KV + conv + SSM) as one file; `/v1/checkpoints/{id}/fork` and `/v1/turn` continue from it with
  the same greedy ids as recomputing the prompt, 28/28 on the identity gate every commit.
- **Agent turns under 60 ms.** On an 8k prefix the engine still holds, a turn with an 8-token
  suffix answers in 41.6 ms, a repeated template turn in 11.5 ms, a fresh 15-token suffix in
  68 ms (was 282 ms this morning). The front reports `ttft_s` and the tier the prefix came from.
- **State files load fast and small.** int8 state files (`BAROST02`, 4x smaller KV) load a 32k
  prefix in 0.20 s on the f32 engine; the int8-KV engine (`--kvq int8`) keeps its own pages
  (`BAROST03`) and loads them in 0.061 s. Two servers on one host share checkpoints; another
  host imports one over HTTP (`/v1/checkpoints/{id}/file`, `/v1/checkpoints/import`).
- **Chat with checkpoints.** `"checkpoint": true` on `/v1/chat/completions` returns the rendered
  prompt's checkpoint id; `"checkpoint_id"` continues from it.
- **Vision, audio, grammar, sampling, MoE**: everything the previous unreleased tree served is in
  this first release (see Commits).

## Changes

### Added
- Checkpoint API: create, fork, list, delete, 409 on pack or weights identity, TTL, live cap
  (`BARO_CKPT_API`, 507), disk budget (`BARO_CKPT_DISK_BYTES`, 507), cross-process sharing through
  `BARO_CKPT_DIR`, `weights_uuid` from the pack.
- `/v1/turn` (TTFT, tier), `/v1/checkpoints/{id}/file` + `/v1/checkpoints/import`, `/metrics`
  (Prometheus text), chat `checkpoint` / `checkpoint_id`.
- State file formats `BAROST02` (int8 KV, default) and `BAROST03` (int8-pool engine pages);
  `BARO_STATE_INT8=0` keeps `BAROST01` (f32).
- `latentos/` package with the boot actors (canonical here; AMDHQ points at it).
- Gates: `bench/state-gates.sh`, `bench/state-timing.sh`, `bench/replay-m.sh`,
  `bench/turn-api.sh`, wired into `run-tests.sh`; `docs/STATE.md`; state knobs in
  `docs/settings-template.toml`.
### Changed
- Hot fork by reference: a fork of a prefix the engine still holds skips the file (P2a).
- Fork request line carries the suffix only; the engine prepends the file's token list (P2b).
- Prompt rows already in the pool replay 4 at a time (`BARO_REPLAY_M`, was 8): 15-token suffix
  0.113 -> 0.068 s, bit-exact.
- State load goes through one pinned stage per engine (no per-load allocation, direct reads,
  parallel dequant): f32 32k 2.57 -> 0.23 s, int8 32k 0.47 -> 0.20 s.
- `amar_ssm_reduce_gates` one block per row; draft-KV memsets only under spec.
### Fixed
- Six `WindowCfg` callers the vision merge left behind (run-tests and ci-checks bench builds).
- `serve/test_serve_proto.mojo` after the request-line change.
### Removed
- The latent-meaning research thesis (E8, E11b, E13, E16): closed as inert, with receipts.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- A fresh 15-token suffix still costs 68 ms (four 4-row replay windows, 71% of it the q4 GEMM at
  460 GB/s); under 60 ms needs a suffix of <= 8 tokens or a repeated one.
- A checkpoint does not survive an unrelated request on the device (it reloads from the file,
  0.06-0.20 s); the host-pinned tier is not built.
- Cross-host routing per request is not wired (`handoff.rs` is fit, not served); import is a
  manual pull. A state file is the prompt in another encoding: ship it over a private or
  encrypted link only.
- int8 KV is a build flag, not the default: its greedy ids differ from f32 on ~1-3% of positions
  (teacher-forced agreement 96.9-99.9%). The MoE profile has no int8 pool.
- All load numbers are page-cache hot; NVMe-cold is unmeasured.
- `docs/STATE.md` has not yet been used by a fresh reader to fork a checkpoint (the check for it).
- Text endpoints need a tokenizer next to the pack or `--tokenizer` + `--chat-template-file`.

## Upgrade / run

<!-- Exact commands. Migrations, new deps, service restarts, config keys. "None" if nothing changed. -->
```
./.venv/bin/mojo build --target-accelerator gfx1100 serve/engine.mojo -I . -I kernels -o .work/engine   # add -D BARO_KVQ=int8 for the int8-KV engine
cargo build --release --manifest-path serve/Cargo.toml
BARO_PACK=<pack> BARO_CKPT_DIR=.work/ckpts BARO_TMAX=32768 serve/target/release/baro-serve --engine .work/engine --pack <pack> --port 8080
```
Packs: `tools/baro run MODEL.gguf --no-serve`. First release: no migration. f32 `BAROST01` files
still load on the f32 engine; the int8 engine reads `BAROST03` only. New knobs: `BARO_CKPT`,
`BARO_CKPT_DIR`, `BARO_CKPT_API`, `BARO_CKPT_DISK_BYTES`, `BARO_STATE_INT8`, `BARO_REPLAY_M`
(`docs/settings-template.toml`).
