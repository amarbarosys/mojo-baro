# mojo-baro v0.3.0

**Released:** 2026-09-24 · **Commit:** `11412f4` · **Previous:** [v0.2.0](v0.2.0.md)

## What it does

An LLM inference engine for AMD RDNA3 GPUs, with every GPU kernel written in
[Mojo](https://www.modular.com/mojo). It serves chat over an OpenAI-compatible
HTTP API on a single RX 7900 XTX. On matched weights it decodes ahead of
llama.cpp on the dense 9B (Q4_0) and level with it on the 35B MoE; on q8 and
on packs built from Q4_K_M it is still behind.

The point of the project is the kernels. Consumer RDNA3 cards are where most
people actually have 24 GB of VRAM, and they are not what the vendor libraries
are tuned for. This repo measures how much of that gap is real, one
preregistered round at a time.

**Have an AMD GPU that isn't a 7900 XTX?** Your card is the most useful thing
you can contribute. See [docs/amd-family.md](docs/amd-family.md): fifteen
minutes, no model weights needed.

## Highlights

- **LatentOS Zero-Copy Brain Fork & Resume.** Instant RAM snapshot (`memfd` + `F_SEAL_WRITE`) of live GPU state (`52.69 MB` SSM+Conv) minted in `5.05 ms` and restored in `3.95 ms` (`67.6x` faster than `266.92 ms` cold prefill), with `100%` bit-exact token identity across poisoned state restores.
- **BAROKV7 State Compression.** Plane-split floating-point state format with zero-expansion `0x7F` escape-RLE and `0x7E` zero-mantissa elision cuts SSM/Conv state checkpoints in half (`67.17 MB -> 34.10 MB`, `1.970x` compression, `-33.08 MB`), speeding up disk load read time from `4.59 ms -> 2.39 ms` (`1.92x` faster).
- **Kimi-K3 Hyperoptimizations (K3-1..K3-4).** Lease-boosted `Pin+LRU` expert tiering eliminates `287.0 MB` of PCIe traffic across 96 tokens; two-stage multi-row MoE union-verify deduplication reduces expert weight loads `2.86x` (`40 -> 14` loads per layer).

## Changes

### Added
- `BARO_STATE_KV7=1` state checkpoint format (`serve/engine.mojo`, `docs/settings-template.toml`, 70 documented settings).
- `amar_split_bf16_planes` and `amar_merge_bf16_planes` GPU kernels in `kernels/state.mojo` (`0` byte lossless round-trip on `gfx1100`).
- `gguf-experts sim-cache` tool in `~/iTools/llm/gguf-experts/gguf-experts.mojo` + Python oracle `tools/sim_expert_cache.py` (`0` byte diff on `520 B` `PIN1` binary).
- Live GPU proof driver `.work/k3-opt/driver_latent_fork.py` and visual dashboard generator `.work/k3-opt/render_proof_plate.py`.
### Changed
- `serve/expert_tier.mojo` uses lease-boosted `LayerLru.touch` (`used_at = clock + cap`) and exposes `effective_hit_rate = (hits - prefetch_reads) / refs`.
- Default settings flipped: `BARO_MOE_DOT=1` and `BARO_TIER_ZC=1` default enabled.
### Fixed
- `LatentStore.put` duplicate file descriptor leak (`8-50 MiB` shmem leak per duplicate `put` fixed to `0 B`, `EBADF` verified).
- `sys_posix_spawn` stack `InlineArray` conversion eliminating heap allocations per process spawn.

## Known limits

- GPU encode for vision prompts requires ~1 GB VRAM; dense engine checkpoints with images remain open.

## Upgrade / run

Set `BARO_STATE_KV7=1` in `docs/settings-template.toml` or environment:
```bash
BARO_STATE_KV7=1 BARO_TIER_PIN_FILE=.work/k3-opt/hot_experts_top1024.bin ./.venv/bin/mojo build serve/engine.mojo
```
