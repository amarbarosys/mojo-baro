## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- The Qwen3.8-Flash-Next engine (`serve/q4x.mojo`) can stay loaded: `Q4X_STDIN=1` serves one request per stdin
  line, so 21 requests took 39-48 s in one process instead of about 7 s each as separate processes, and the expert
  cache stays warm (28 misses per token in steady state against 90 cold). Outputs equal the one-shot CLI.
- The first request is faster too: a default warm list cuts its expert misses from 90.6 to 33.5 per token
  (18.1 vs 21.4 ms/token).

## Changes

### Added
- `Q4X_STDIN=1` resident mode: requests `TAG N_GEN TOK...`, answers `out TAG ids ...`, state reset between requests
  (`a61876b`).
- `Q4X_CHUNK=N`: single-sequence prefill as N-token forwards, byte-identical to one forward; opt-in for a Q4X_TMAX
  whose batch buffers do not fit VRAM.
- `bench/q4x-serve-check.sh` and its prereg `bench/q4x-serve-protocol.md`.
### Changed
- q4x loads `FIRST_SHARD.warm` as its warm list when that file exists (`Q4X_WARM=0` turns it off).
- q4x expert cache leaves 0.5 GB of VRAM free instead of 1.5 GB: 6.6% more slots, 17% fewer steady-state misses.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- Margin speed is order-confounded: misses fall 17%, but gen ms/token read 1.096 and 0.985 in the two ABBA pairs; the
  first resident arm of every job runs slow, cause unknown.
- Chunked prefill is 1.5x slower than one forward at 8192 tokens (each chunk refetches its experts).
- Resident mode has no HTTP front; one request at a time over stdin.
