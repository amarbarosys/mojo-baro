# mojo-baro v0.5.3

**Released:** 2026-10-12 · **Commit:** `7ac92ed` · **Previous:** [v0.5.2](v0.5.2.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

- **Correction to v0.5.2:** its "59 of 66 valid" spark result was false. That spark engine produced all-zero
  logits (its token embedding was never written) and the grammar mask alone picked the tokens. Spark now runs the
  real model, and the same gate passes 66 of 66 with the masked-draw receipt matching on every request.
- Spark bakes build their weight pack with the Mojo pack tool: 20.7 s and 2.60 GB peak memory, against 35.6 s and
  6.55 GB for the Python tool, with byte-identical output.

## Changes

### Added

- Spark prints the `grammar masked draws / accepted / terminated` receipt for each grammar request (`cd53675`).
### Changed
- Spark bakes embed the Mojo pack tool and its sources; `tools/baro serve` and `tools/baro verify` both build the
  pack with it through `tools/pack-run.sh` (`7ac92ed`).
### Fixed
- Spark decodes again: the token embedding lookup that c7ef948 removed is restored (`cd53675`).
- `tools/baro verify` on a spark bake: its kernel closure now carries `tools/gguf_reader.mojo` (`7ac92ed`).

## Known limits

- No llama.cpp oracle for spark2_5: current llama.cpp (`ca3d5a3e1`) refuses the arch, so spark identity is checked
  against its own reference ids, not an outside runtime.
- The first spark bake on a machine builds the Mojo pack tool once (cached beside the closure afterwards).
- Bakes made before `7ac92ed` still carry `spark-pack.py` and keep working with it.
