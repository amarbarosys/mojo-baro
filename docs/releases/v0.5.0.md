# mojo-baro v0.5.0

**Released:** 2026-10-12 · **Commit:** `7b032bb` · **Previous:** [v0.4.0](v0.4.0.md)

## What it does

An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

- Dense 9B decode is 2.4% faster: 148.80 tok/s_gen (was 144.50), same output token for token.
- The 35B MoE uses half the KV cache memory by default (int8 KV), at the same quality as an f32 reorder control,
  and decodes 1.077x faster past 32k context.
- `tools/baro serve` rebuilds its engine when the kernels change, and `/v1/state` reports the KV cache type.

## Changes

### Added
- `/v1/state` reports the running KV cache type; state import accepts BAROST03 files (`71625a4`).
- `serve/wstore.mojo`, a weight store that places GGUF tensors on mmap / pinned / ring / cache host tiers, groundwork
  for models larger than VRAM (`085a012`, not wired into an engine yet).
### Changed
- Dense megakernel: 88 fewer grid barriers per token (`c5034a4`), the 148.80 champion.
- qwen35moe builds default to int8 KV (`f3220ad`); `-D BARO_KVQ=f32` restores f32.
- MoE serving and bake verification run in tier mode only (`78d331a`): the resident 20 GB pack crashed the desktop
  session next to KDE on 2026-10-12.
### Fixed
- Serve engine cache keyed per kernel commit, so a new bake never runs a stale engine (`966df74`).
- Bake closure: `kernels/state.mojo` and the grammar package are embedded (`e40d9ca`); the tokenizer tool is rebuilt
  when stale (`ad00fe4`).

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- `tools/baro verify` on a MoE bake fails by design under int8 KV: the bake's reference ids are f32 greedy and
  int8 flips position 8. Re-referencing the bake is an open decision.
- Resident MoE serving is not supported next to a desktop session; use tier mode.
- 475 commits since v0.4.0. This note lists the user-facing changes verified on 2026-10-11/12; earlier commits in
  the list below were not re-audited for it.
