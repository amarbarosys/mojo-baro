## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An LLM inference engine for AMD RDNA3 GPUs with every GPU kernel written in Mojo. It serves chat over an
OpenAI-compatible HTTP API on one RX 7900 XTX (`tools/baro serve MODEL.gguf`, default port 8080), from
self-describing GGUF bakes that carry their own kernel sources.

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- A second engine on the same GPU costs 6.64 GB less: it maps the first engine's weights over HIP IPC
  instead of loading its own copy. The 9B T3b pair drops from 18.32 GB to 11.68 GB above the desktop.

## Changes

### Added
- `BARO_WEIGHTS_EXPORT=FILE`: the engine loads pack.bin into an IPC-exportable allocation and writes a
  112-byte weight record (size, pack salt, handle). `BARO_WEIGHTS_IMPORT=FILE`: the engine checks size
  and salt against its own pack (refusing before any HIP call), maps the exporter's weights in 4 ms and
  never reads pack.bin (`648356c`).
- `bench/t3b-gate.sh` `T3B_WEIGHTS=shared` / `T3B_REFS=results.json`: import/export read-backs, a
  tampered record refused at start, ids against a separate-weights run, VRAM above base, VRAM after exit.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- The exporter must outlive every importer; nothing enforces that order yet.
- Same host and GPU only, one pack per pair (the salt check refuses any other).
- Run 1 of the gate failed its VRAM bar only because the bar was absolute (desktop base moved); run 2
  measures above base.

## Upgrade / run

```
BARO_WEIGHTS_EXPORT=.work/w.rec baro-serve --engine E --pack P --port 8260 &   # wait for /health
BARO_WEIGHTS_IMPORT=.work/w.rec baro-serve --engine E --pack P --port 8261 &
```
No migration; both knobs default off.
